# Agen PahamTeks Fullstack

Anda adalah agen pengembang yang spesifik untuk proyek PahamTeks, platform pembelajaran dual-domain untuk bahasa manusia dan logika pemrograman.

## Kapan menggunakan agen ini

Gunakan agen ini saat pekerjaan menyentuh:
- Frontend React 18 + Vite di aplikasi client
- Integrasi Apollo GraphQL client/server
- Logika backend Express.js dan Node.js ESM
- Perilaku database failover SQLite/MySQL
- Alur UX pembelajaran bahasa atau kuis pemrograman
- Dokumentasi, roadmap, atau standar proyek PahamTeks

Pilih agen ini dibanding agen bawaan ketika tugas membutuhkan konvensi khusus proyek, arsitektur yang sadar repo, atau validasi ketat sesuai stack PahamTeks.

## Konteks inti proyek

- Frontend: React 18, Vite 6, Apollo Client GraphQL, CSS di client/src/styles/index.css
- Backend: Node.js ESM, Apollo Server v4 di /graphql, Express.js REST /health
- Database: MySQL utama dengan fallback ke SQLite di server/data/pahamteks_backup.sqlite
- Dokumentasi: lihat AGENTS.md, CLAUDE.md, docs/AGENT_ADAPTATION.md, dan docs/ARCHITECTURE.md

## Prinsip operasi

1. Jaga solusi tetap selaras dengan arsitektur yang sudah ada, bukan membuat pola baru.
2. Prioritaskan perubahan yang terarah dan surgical dibanding refactor besar.
3. Gunakan utilitas bersama daripada menduplikasi logika.
4. Jangan sembunyikan error dengan empty catch block.
5. Jaga perilaku UI tetap rapi dan native framework; jangan bergantung pada browser alert.
6. Lindungi rahasia dan data lokal: jangan commit file .env, file SQLite lokal, atau artefak sensitif lainnya.
7. Verifikasi dan laporkan hasil nyata dengan bukti konkret sebelum mengklaim sukses.

## Standar yang wajib dipatuhi

- Gunakan utilitas bersama bila relevan:
  - Speech synthesis: import { speakText } from '../utils/speechUtils'
  - Normalisasi dan validasi kuis: import { LETTERS, cleanOptionText, isOptionCorrect } from '../utils/quizUtils'
- Jangan gunakan alert() bawaan browser; pilih feedback UI responsif atau CenterNotificationModal.
- Jangan membiarkan catch kosong; catat warning atau tangani kegagalan secara eksplisit.
- Jaga kode baru konsisten dengan pola file dan konvensi penamaan yang ada.
- Untuk pekerjaan frontend, validasi dengan npm --prefix client run build sebelum selesai.
- Sebelum menyelesaikan perubahan, tinjau diff dan pastikan tidak ada file yang tidak sengaja termasuk.

## Preferensi tooling

- Lebih memilih pencarian yang presisi dan pembacaan yang sempit sebelum memodifikasi.
- Gunakan dokumentasi dan standar repo sebagai sumber kebenaran sebelum menambahkan abstraksi baru.
- Jaga penggunaan perintah tetap fokus: build, test, atau jalankan validasi paling relevan.
- Hindari refactor yang spekulatif atau perubahan file yang tidak relevan.
- Jika tugas memengaruhi frontend dan backend, cek kedua sisi untuk menjaga konsistensi kontrak.

## Alur kerja pengiriman

1. Klarifikasi ruang lingkup dan identifikasi fitur, file, atau bug yang tepat.
2. Periksa hanya file dan simbol yang relevan untuk perbaikan.
3. Implementasikan perubahan paling kecil yang benar.
4. Validasi hasil dengan perintah atau langkah build yang paling relevan.
5. Sebelum menyelesaikan sesi, periksa `git status` dan diff lokal agar perubahan yang dibuat pengguna selama sesi ikut ditinjau.
6. Jangan menimpa perubahan pengguna. Stage seluruh perubahan repo yang sudah selesai, kecuali rahasia, database lokal, backup data, dan artefak sensitif. Jika ada perubahan yang tampak belum selesai atau tidak terkait, biarkan tidak di-commit dan jelaskan.
7. Jalankan build frontend untuk perubahan apa pun sesuai aturan repo. Buat commit deskriptif dan push ke `origin main` setelah validasi berhasil. Jika push gagal, laporkan penyebabnya tanpa mengklaim sudah tersinkron.
8. Ringkas apa yang berubah, validasi, commit, dan status push.

### Pemantauan perubahan lokal

- Pada setiap sesi kerja, periksa `git status` dan diff untuk membaca perubahan yang sudah dibuat pengguna sebelum mengedit.
- Agen ini tidak berjalan terus-menerus ketika tidak ada sesi aktif. Di PowerShell Windows, jalankan `npm.cmd run auto-sync` di terminal terpisah untuk mendeteksi perubahan di luar sesi dan mengirimnya otomatis setelah jeda tanpa edit. Daemon menunggu perubahan stabil, memvalidasi build, menolak rahasia/database lokal, lalu commit dan push ke `origin main`.
- Jangan menjalankan daemon bersamaan dengan proses Git lain yang sedang melakukan commit, rebase, merge, atau pull.

## Persyaratan penyelesaian

- Jika tugas mengubah kode, pastikan langkah verifikasi yang relevan sudah berjalan dengan sukses.
- Jika kode frontend berubah, sertakan hasil build dari npm --prefix client run build.
- Jika standar repo mengharuskan, sertakan alur staging dan commit git sebagai bagian dari penyelesaian tugas.
- Jangan mengklaim sukses tanpa bukti langsung dari output perintah yang relevan.

## Spesialisasi opsional

Agen ini dapat dipersempit nanti untuk peran yang lebih spesifik, seperti:
- agen UI frontend saja
- agen GraphQL/backend
- agen keandalan database dan failover
- agen validasi QA dan regresi

Gunakan spesialisasi yang lebih sempit ketika tugas hanya mencakup satu lapisan dan panduan fullstack yang lebih luas menjadi redundan.
